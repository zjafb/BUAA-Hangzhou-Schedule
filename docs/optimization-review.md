# 稳定性与可维护性优化记录

## 本轮实现

保留 shared（API、存储、仓库）、composeApp（状态与界面）、androidApp（Android 入口）的现有分层。本轮围绕请求生命周期、缓存失效和常用页面完成调整，没有替换多平台框架。

- 增加 `requestResult` 请求边界：传播协程取消、捕获普通请求异常，并检查调用结束后任务是否仍有效，阻止已取消任务更新页面。
- 希冀列表、详情、考试、成绩、成绩更新检查、空教室查询持有任务引用；刷新或重置时取消对应旧任务，加载入口防止重复触发。
- 希冀仅在成功后记录已加载；失败后可重新请求。刷新保留已有列表，后台详情补全设总超时，批量失败时停止连续补发请求。
- 学期仓库增加缓存世代检查；切换连接状态清空缓存后，旧响应不能重新填入缓存。
- 成绩历史查询限制为 3 个并发；单个历史学期失败不丢弃后续结果，刷新保留选中学期并清理已不存在学期的缓存。
- 普通、高级功能共用卡片组件与稳定列表键，保持一致尺寸和高级功能底部提示。
- 教学楼名称搜索保留楼内教室；考试页面增加失败重试与空状态文案。保留 `.ics导出` 文案及此前缩小字号的调整。

## 验证与边界

新增回归覆盖：希冀失败重试、并发入口去重、忽略取消的后端迟到响应、教学楼名称搜索、成绩并发上限及部分失败、学期缓存失效期间的迟到响应。

Android Debug 构建通过。Compose JVM 测试通过直接 JUnit 入口执行；本机 Gradle JVM 测试入口发生测试类加载失败，同一编译产物与依赖通过直接 classpath 可以运行，尚未修复该运行器问题。

共享模块直接 JUnit 执行 91 项测试时有两项失败：

1. `LocalAuthServiceBackendTest`：登录统计在 IO 协程异步上报，测试立即读取可变列表，存在时序不稳定。
2. `ScheduleTimelineTest`：测试要求旧数据缺失节次时间保留空值，目前实现会用固定 14 节标准作息补全。需要统一产品作息规则与测试约定，不能仅为通过测试改写时间。

本轮没有验证真实账号的希冀登录和作业查询，也不能由客户端优化推断中转服务器已恢复。iOS、Web 和真实设备交互尚未完成回归。本记录不代表整个软件已经完成全面重构或所有问题均已解决。

## 后续：会话与布局优化

- 增加会话级 ViewModel 容器，按用户和连接方式隔离。会话改变或退出应用主界面时统一清理页面状态和任务，包括未显示的页面；连接方式切换后回到首页。
- 移除主界面重复的手动重置及强制加载分支，页面初始化统一通过导航加载入口完成。
- 普通和高级功能共用自适应网格：常见手机宽度保持两列，窄屏或大字体减少列数，宽屏最多四列；两页使用相同卡片尺寸策略，底部提示仍在网格内占整行。
- 邮件未读刷新取消前一次任务；查询失败保留上次总数，不再把失败账户当作零未读写入缓存。
- Android Debug 构建成功，直接 JUnit 运行的 Compose 模块 71 项测试通过。新增实际 Compose UI 测试验证会话释放、两类卡片尺寸一致和页脚不重叠，并测试窄屏与字体缩放的列数策略。共享模块和 Gradle 测试入口的上述已知问题仍未解决。
